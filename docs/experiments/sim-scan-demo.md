# 仿真扫描与多布局回看

## 启动与操作

使用 [本地工作台启动命令](../../src/README.md#本地启动工作台) 构建并启动 FastAPI，按 [P3 GPU 环境说明](workbench-gpu-smoke.md#启动与复现) 启动真实 Worker。两个进程使用同一数据目录和端口。本次验收使用 18466 端口及独立数据目录。

1. 在 Edge 新建虚拟相机场景。保持展品的初始位姿，从「虚拟相机」选择「背面」预览黄色 07 徽章。
2. 点击「环拍并上传 24 张」，待全部受理后确认批次 v1。连拍的相邻球位相隔 15°，机位高度角在 21°、25°、29° 之间交替。虚拟图像使用固定的 960 × 720 像素画幅和 40° 垂直视场角，页面大小只影响显示。
3. 对 v1 分别提交「多图点云融合」和「3DGS 实景重建 → 普通重建」。待任务轮询完成，使用点云和 3DGS 标签环绕，也可在批次原图中打开直拍徽章的第 13 张照片。
4. 切回「照片采集」，打开「虚拟相机」，移动及旋转展品，在新位姿补拍。确认批次 v2，提交点云融合。在「查看批次」切换 v1/v2，分别核对原图、点云和对应批次的 3DGS 结果。

照片以 `[sim-v1:X,Z,R]` 记录仿真布局，其中 X 和 Z 是以场景单位的百分之一记录的展品平移，R 是绕竖直轴旋转的度数。球位和镜头高度不改变布局编号。工作台分布局选择采集照片，API 在确认批次时校验布局一致性。冻结批次保留原图顺序和照片标识，历史作业与产物按批次独立保存。

连拍和单拍都会记录虚拟相机方位、高度角和距离。DA3 多图融合用这些位姿和固定内参复原展品的正背面。COLMAP 仍从原图独立完成注册，再用虚拟机位将重建的竖直轴对齐到场景，方便在 SuperSplat 中以展品为中心环绕。浏览器里的普通照片继续使用原有估姿方式。

## 本机实测

2026 年 11 月 24 日，Windows、Edge 158.0.4370.33、RTX 4060 Laptop GPU 8 GB、NVIDIA 驱动 621.24。使用 P3 相同的 DA3-BASE 权重和独立的 DA3、3DGS Python 环境，3DGS 使用 Brush 0.3.0 和 SplatTransform 3.12.0。端到端时间从网页提交到查看器首次可用，包含 Worker 领取、计算、发布、网页轮询和模型加载。

| 批次与作业 | 端到端 | 结果 |
| --- | ---: | --- |
| v1 布局 A，24 图 DA3 `fusion/v1` | 15.628 秒 | 200,000 点。GLB 3,201,136 字节，清单 7,669 字节，24 张深度预览。 |
| v1 布局 A，24 图 3DGS `splat/v1` | 243.657 秒 | COLMAP 注册 24/24，Brush 训练 8,000 步，共 44,885 个高斯。PLY 10,594,410 字节，SOG 778,991 字节，清单 4,491 字节。 |
| v2 布局 B，6 图 DA3 `fusion/v1` | 14.180 秒 | 200,000 点。GLB 3,201,196 字节，清单 2,483 字节，6 张深度预览。 |

布局 A 的 24 张原图均为独立哈希的 960 × 720 RGB PNG。第 13 张原图、环绕至背面的点云及 SuperSplat 中的 SOG 都能读到同一个黄色「07」徽章。3DGS 各阶段实测为图像准备 1.843 秒、COLMAP 22.181 秒、Brush 训练与 PLY 导出 214.851 秒、SOG 导出 2.141 秒。

布局 B 将展品沿 X 轴移动 0.70 个场景单位并转动 −175°。在较窄的浏览器窗口用 6 个相邻机位单拍，输出分辨率不变。混选 v1 和 v2 原图时 API 返回 422。工作台切回 v1 后能重开原图、点云和 SOG。切回 v2 只显示本批次的原图和点云。

用同一数据目录重启 API 后，Edge 重新打开了两批的原图、点云和 v1 的 SOG。核对了 30 张原图的 SHA-256、三份清单的有序输入、所有下载的大小、30 张深度预览的 JPEG 解码，以及 PLY 和 SOG 的高斯数。切换标签后，虚拟相机与点云的 WebGL 上下文均已释放，切换批次时 3DGS iframe 随之卸载。前端 TypeScript 和 Three.js 分包校验通过，17 项后端测试通过。
