# SplatForge 灵境智绘 · 视觉模块设计与验收规范

**版本** v0.1 · 评审稿　　**日期** 2026-11-26

## 1. 产品目标与首版范围

答辩操作者可以在同一个工作台移动仿真蛇头相机，查看低机位与抬头机位的 RGB 与深度，补拍展品并对照前后点云，再打开该展品的 3DGS 资产，绕到背面核对一个正面看不到的细节。评委能够从结果回到原始照片，判断新增表面来自哪个机位。

| 范围 | 交付内容 | 当前依据 |
| --- | --- | --- |
| 首版主线 | 本地仿真工作台、单件展品、RGB／深度预览、补拍前后点云对照、同一布景的交互式 3DGS | 仿真简版已有机位切换、采集、点云融合和预生成 3DGS 浏览记录 |
| 首版真实素材验证 | 手机采集一件展品，生成一份可在工作台打开的高斯资产，保留原始素材和作业记录 | 公开照片已有本机重建基线，自采物体待验证 |
| 条件扩展 | 实体蛇形机器人拍摄、云 GPU 复跑、公开室内资产展示、自录局部空间重建 | 分别以设备画面、云端作业或独立展示结果验收 |
| 研究候选 | 学习式点云补全、较新的 3DGS 方法、真实整室连续漫游 | 按目标缺陷和实验收益决定是否纳入 |

3DGS 发布版优先满足局部画质要求，再优化加载和交互。场景卡片与查看器内常驻三类来源标签：**`仿真·虚拟采集`**、**`实拍·赛前预制`**、**`实拍·现场云端重建`**，便于评委清晰核对机位真值、赛前预制原图与现场作业状态。团队实拍阶段以手机验证采集流程，实体蛇形机器人阶段另做低机位可达性、蛇头结构视野、抬头动作与停稳画质验收。 [现有实测记录](../experiments/public-sample-benchmark.md)

## 2. 工作台交互

| 页面或区域 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 首页 | 从项目介绍进入扫描台或示例库 | 显示项目名称、视觉能力入口及三类来源标签（`仿真·虚拟采集`、`实拍·赛前预制`、`实拍·现场云端重建`） |
| 扫描台 | 选择展品、调整仿真蛇形机器人的低机位与抬头机位、停稳后采集，也可运行预设环拍 | 显示当前机位、已采照片、RGB 与对应深度。仿真真值和模型估计分别标识，深度注明单位或相对尺度 |
| 点云对照 | 先查看初扫结果，再补拍背面，按同一观察视角比较两批结果 | 显示批次、点云和来源照片。统一坐标和尺度后启用同视角对照 |
| 3DGS 查看器 | 选择已生成的资产，拖动或切换固定机位，查看背面标记和局部细节 | 显示资产所属布景、生成批次、来源及对应原图。预生成资产显示其实际训练批次 |
| 作业与结果 | 提交一批照片，查看状态，失败后查看原因或重试 | 显示当前阶段、错误摘要和可用结果。已有成功资产在新作业期间仍可浏览 |

仿真简版继续作为本地演示入口。首轮工作台集成可以由人工运行离线作业、登记资产，再通过网页查看。自动提交与进度查询在文件交接稳定后接入。展品摆放改变时新建布景版本，该版本有独立的采集与结果记录。

## 3. 处理链路与交接规范

**取景或导入 → 保存有序照片批次 → 深度与点云预览／3DGS 后台重建 → 登记产物 → 网页查看**

| 环节 | 输入与处理 | 交付 |
| --- | --- | --- |
| 采集 | 仿真 RGB-D 与已知位姿，或手机／实体蛇形机器人 RGB。视频先抽帧，再筛除模糊和重复画面 | 有序 RGB、来源、布景版本、原片与抽帧参数。仿真附深度、单位、内外参 |
| 深度与点云 | 仿真用已知参数反投影和融合。实拍先复用 DA3-BASE，以需要的深度预览、点云和原始中间数据为输出 | 深度预览、点云 GLB，按需保存置信度、原始深度与相机参数 |
| 3DGS | 实拍先用 COLMAP 注册，沿用 Brush 本机基线优化。仿真使用已知机位的基线流程 | 配准结果、完整 PLY、浏览 SOG、留出渲染与作业清单 |
| 浏览与发布 | 静态页面加载已通过检查的资产。采用固定起始机位和观察路径复核 | 视觉结果、输入追溯、可离线打开的演示包 |

每批照片绑定**场景 ID、布景版本、批次 ID、采集来源、照片顺序及哈希**。每次运行绑定**作业 ID、输入批次、处理类型、环境、参数、运行阶段、错误和产物路径**。短轮、正式训练和重试分别使用独立输出目录。失败时保留日志，只有清单所列产物可读且校验完成的作业才能登记为可展示。首轮沿用现有 manifest 与 CLI 约定，在集成层补齐场景和批次关联。 [系统架构](platform-architecture.md) · [作业入口](../../src/README.md)

## 4. 技术选择与实验设计

### 4.1 深度与点云

首版将“补拍”定义为新增观测，演示采用同一布景的初扫批次和包含初扫照片的补扫批次，锁定尺度、坐标和观察机位。用新拍背面照片核对新增表面，并检查薄边是否被过滤。仿真有参考几何时，记录覆盖率、点到参考表面的误差和飞点情况。实拍初轮用照片做视觉复核，取得独立参考几何后再报告精度。

学习式补全是独立实验。只有在参考几何能够核对未观测区域时才比较补全收益。若进入演示，界面需标示推断区域，保留原始观测点云供对照。

### 4.2 3DGS 画质

工程基线沿用仓库现有 COLMAP＋Brush。新方法优先从团队关注的 2025–2026 年候选中筛选，先写明要改善的缺陷，例如近景边缘拉伸、贴纸模糊或遮挡处重影，再检查复现条件和资源预算。DN-Splatter 可列入调研。若开展论文方法对照，将 2023 年原始 3DGS 官方实现作为单独的实验基线，记录实现差异。

候选固定照片、训练与留出划分、对照视角和目标裁框。可复用同一相机位姿时保持一致，否则记录差异及其对比较的影响。以背面标记、薄边和遮挡区域的局部画面作为选型依据，记录 PSNR、SSIM、最差视角、耗时、峰值显存和资产大小。确认候选后再用独立自采场景复核。 [质量实验细则](../experiments/visual-quality-plan.md)

### 4.3 手机素材试采

第一轮选一件有纹理、背面带清晰标记的桌面展品，保持物体和灯光固定，移动相机覆盖正面、两侧、背面与相邻过渡位。建议先采 **24–32 张有效照片**作为试验起点。视频路线先试拍 **12–16 秒**的移动片段，按 **2 帧／秒**抽取约 **24–32 张候选帧**，筛选后按实际覆盖补拍。两种路线选一条先完成。若关键机位无法注册，优先补缺失视角并排查模糊、反光和重叠，再调整采样数量。

## 5. 云端范围与工作量

| 级别 | 需要配置 | 工作量主要来自 |
| --- | --- | --- |
| 离线素材加网页展示 | 一次本机或云端作业、产物导出、网页静态目录 | 素材采集、重建质量和网页兼容性。已有公开资产可以独立演示 |
| 云 GPU 手工复跑 | 单台可访问的 GPU 实例、锁定的软件和模型版本、输入与输出目录 | 环境安装、素材上传、短轮复跑、耗时与显存记录、资产下载。可先用同一公开批次验证 |
| 网页自动提交云作业 | 前两项加 API、作业记录、队列与执行器、文件存储与受控访问 | 上传、状态同步、失败重试、结果发布及无人值守验证 |

首轮先交付本地演示。若本机无法按要求生成正式资产，或答辩需要验证端云作业，再做手工云 GPU 复跑。网页展示使用已生成资产，重建时间和浏览加载时间分别计量。全景图定点观看、公开 3DGS 漫游和自采整室重建按各自来源和交互能力说明，整室扩展从局部空间试采开始。 [云端试跑手册](cloud-pilot.md)

## 6. 发布验收

| 编号 | 测试动作 | 首版通过条件 |
| --- | --- | --- |
| V1 | 切换机位并采两张，随后更换展品或改变摆放 | RGB、深度与机位对应。当前布景照片能回看，更改布局后产生新布景版本 |
| V2 | 在同一展品上做初扫与背面补扫 | 可按同视角比较点云，在补扫结果中指出至少一处新增可见表面，并打开对应原图核对 |
| V3 | 打开同布景的 3DGS，从正面移动到背面 | 可连续控制视角，在固定背面机位辨认标记，可以对照原图并确认资产训练批次 |
| V4 | 用手机采集独立真实素材，完成一轮本机处理 | 保留原片和入选图，正侧背关键机位均注册，生成可打开的资产并记录失真局部 |
| V5 | 在演示机断网，从新解压目录完成一遍主流程 | 首页、工作台、点云与已生成高斯均可打开，网页状态和来源可读。同时记冷加载、首次可交互和固定路径的帧间隔 P95 |
| V6 | 提交一次缺图或无法完成配准的批次 | 能找到输入批次和失败阶段。修正输入可重新提交，已有成功结果可继续打开 |

表中为拟定的首版门槛。加载时间、显存和训练耗时上限在首轮演示机与自采数据实测后由团队确认。每项验收保存测试输入、版本、结果截图或录屏与作业清单。

## 7. 下一阶段分工与决策

| 顺序 | 建议责任方向 | 交付与完成标志 |
| --- | --- | --- |
| 1. 固定演示样例 | 仿真与采集 | 定下单件展品和一个背面标记，冻结初扫／补扫机位与输入列表，先完成 V1、V2 |
| 2. 衔接展示 | 前端与视觉 | 用现有静态包接通原图、深度、点云和高斯入口，完成 V3、V5 |
| 3. 跑通真实素材 | 采集与视觉 | 手机拍摄单件展品，登记注册、画质和耗时，完成 V4，定位最大的质量瓶颈 |
| 4. 完善作业管理 | 集成 | 统一批次与结果索引，处理失败和重试，完成 V6 |
| 5. 评审扩展 | 项目组 | 根据 V4 的失败点决定先补拍、优化高斯还是复跑云端。明确下一轮的单个候选、预算和进入条件 |

本轮评审需确定首个展品、演示设备、各任务负责人，以及真实样例是否必须在答辩现场重新生成。确定后以 V1、V2 和 V4 尽早检验采集与覆盖，再定正式展示资产。
