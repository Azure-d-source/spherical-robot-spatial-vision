# OrbitForge · 球迹视界执行方案

**版本** v0.3　　**日期** 2026 年 11 月 23 日　　**定位** 球形机器人端云协同三维扫描系统

## 1. 交付目标

OrbitForge 把球载取景、多视角几何和 3DGS 漫游串在一项可回看的扫描任务中。用户可在内嵌工作台摆放虚拟展品、移动球体并从第一视角拍摄，也可导入真实照片和视频，生成能追溯到原图的点云与高斯场景。

开发机用于复现和调参，同时准备云 GPU 跑通同批素材。用自有域名提供线上浏览，单文件用于现场回放。视觉作业和产物稳定后，再把仿真、场景导入和作业状态接入正式工作台。深度图按需用于诊断。

| 交付场景 | 输入及操作 | 验收条件 |
| --- | --- | --- |
| 公开真实场景 | 选定一组公开原始 RGB，实际运行配准、训练和 SOG 导出。同时准备一份来源明确的预生成公开室内高斯。 | 自己重建的场景能回查照片、训练设置和留出视角；公开高斯可直接加载并标出来源。两者均验证相机移动和浏览性能。 |
| 自有视频 | 提前导入团队提供的手机 MP4。设定采样区间和频率，筛选清晰、重叠且有视差的关键帧，在本机或云卡上重建。 | 保存原视频、抽帧清单和注册摘要。展示预先生成的结果，并从至少两个已覆盖视角核对书桌、角落或主要轮廓。 |
| 仿真小球 | 可摆放与移动球和展品，球载相机随球体更新位姿。保持一次扫描布局静止，采集正面、过渡、侧面、背面 RGB。 | 可从源图追溯点云新增覆盖，3DGS 中可绕到背面认出标记。移动展品后新照片进入新布局，旧结果仍可查看。 |
| 云 GPU 与自有域名 | 先试一张 4090 或 5090，复用公开原图、锁定版本和留出视角。域名先发布可展示的高斯与查看器。 | 有云机注册、优化、导出、显存及产物记录。线上 HTTPS 页能打开并交互，现场可回放相同版本的独立文件。 |

## 2. 素材和配方

- **拍照。** 相机保持同一焦段，场景静止且画面清楚。相邻照片要有重叠与相机位移。小场景按长边约 1200 px、24–40 张起测，确认关键方向可注册到同一子模型。
- **录视频。** 1080p、固定焦段、缓慢移动。先拍书桌和相邻角落，用移动获得视差，并在相邻画面保留桌边、柜体等共同特征。先做短片段，再决定是否扩大覆盖。 [视频输入](https://docs.nerf.studio/quickstart/custom_dataset.html) · [COLMAP 采集说明](https://colmap.github.io/tutorial.html)
- **场景优化。** 先用 400 步跑通，再固定相机注册、留出视角、分辨率和高斯数上限，对照 2,000 至 8,000 步的细节与耗时。检查边缘、纹理、遮挡和留出渲染，留存实际入选照片、训练与留出分组、参数和软件版本。
- **资产与浏览。** 用同一模型比较 PLY 与 SOG 的首帧、首次可拖动和移动帧间隔。公开室内 3DGS 提供连续视点移动。已有 360° 全景图片可另外用定点旋转与热点跳转展示。 [全景导览示例](https://pannellum.org/documentation/examples/tour/)

## 3. 实施顺序

| 工作 | 与其他任务的关系 | 工程交付 |
| --- | --- | --- |
| 本地视觉基准 | 点云和 3DGS 同时推进。 | 同一公开素材的单图、多图 GLB，按需深度图，原始图到 PLY/SOG 的重建记录。 |
| 云 GPU 试跑 | 与本地调参并行准备，使用同一公开基准。 | 先跑兼容性短轮，再跑经本地校准的参数。记录 GPU 型号、驱动、显存、注册、优化、导出、哈希和成品。实例可用后直接按手册执行。 [试验手册](cloud-pilot.md) |
| 自有视频 | 有素材即可抽帧并跑短轮。 | 按抽帧和注册情况调整取样，固定配置后提前生成正式演示资产。 |
| 域名展示 | 可与云计算独立联调。 | 把有展示权的资产和查看器发布到团队域名的 HTTPS 路径，实测加载时间。在线和本地回放使用有版本的产物。 |
| 仿真工作台 | 复用已验证的输入和输出格式。 | 可移动虚拟球和展品、球载取景、批次、点云对比与高斯浏览。正式界面和服务随视觉结果接入。 |

## 4. 已验证状态与验收记录

RTX 4060 Laptop 已验证公开 32 图注册、短轮及 8,000 步 3DGS、SOG 交互浏览、DA3 单图和多图点云。仿真四机位已生成 RGB 并到本机点云。云 GPU、域名发布、自有视频和仿真完整重建分别以新试验记录验收。

同一批照片进入点云和 3DGS 两条作业。文件交接记录场景、布局、批次、输入哈希、工具配置与产物。失败保留输入和日志，成功校验后才更新展示入口。时间分别记录抽帧、注册、优化、导出、加载和拖动响应。 [系统架构](platform-architecture.md) · [公开样例实测](../experiments/public-sample-benchmark.md) · [交付清单](../competition/submission-checklist.md)
