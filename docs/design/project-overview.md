# 球形机器人端云空间视觉项目总览

2026 年 11 月 22 日 · v0.3 · 团队评审稿

## 1. 我们要做的作品

**用一台带单目摄像头的球形机器人，把一件桌面实物扫描成可以补拍、回看、环绕浏览的数字展品。** 用户在网页上点选玩具，先看首张照片的深度和点云，再根据已拍机位与补拍提示采集侧面、背面和顶面。云端用补拍后的照片更新点云，最后用同一批原图重建带纹理的 3DGS 实景。

首个演示对象选一件有纹理、背面有明显标记的玩具或手工作品，拍摄范围覆盖它和周围一小块桌面。作品面向小型实物的数字展示，适合从玩具展品、手工作品或课程教具切入。参赛方向为人工智能应用中的图像处理与空间视觉，正式题名按赛题要求确认。

**作品的展示重点是 3DGS。** 网页上能从桌面总览切到选中玩具的近景，再沿着已经采集的方向绕看。首拍、补拍、融合点云和 3DGS 都能回到同一个任务核对原图。场景的三维效果来自现有视觉模型与重建方法，团队的开发重点是设备接入、目标引导、任务管理、仿真和三维交互。

### 评审时怎么介绍

**建议题名**　绕物成景——球形机器人目标引导扫描与 3DGS 实景重建

**拟展示的作品**　用户选中一个实物，球形机器人从多个位置为它取景。系统让用户逐步看清哪里已经拍到、哪里还需要补拍，并把同一批照片变成可环绕浏览的桌面展品。真实与虚拟相机使用同一套采集接口。

最能体现工作量的三项证据是**首拍与补拍后的同一处表面对照、真机与虚拟相机上传新照片后各自得到结果、完整高斯场景的现场交互**。现阶段已跑通公开样例的几何估计、重建和本机浏览。答辩材料可引用这些实测，真机、云端和目标引导功能在相应验收通过后再写入完成情况。

## 2. 一次完整扫描怎么走

1. **创建任务，拍第一张图。** 在网页选择真机或仿真。球形机器人到位停稳后用一个 RGB 相机拍摄，板端上传照片并回报状态。云端返回原图对应的相对深度图和初始彩色点云。
2. **选中玩具，确认目标区域。** 用户点选或框选玩具，确认轮廓。首版可以先保留框选与人工校对，随后接入分割模型细化轮廓。识别名称可以进一步用于归档。云端依然保留完整原图，用于估计深度和对齐机位。
3. **按提示换位置补拍。** 界面显示正面、左右侧、背面和顶面的采集状态。操作员判断下一处机位，让球形机器人移动到位再拍。相邻照片保留重叠特征，玩具和桌面在同一批次内保持静止。一个摄像头换到多个位置拍，就能获得单目多视角照片。
4. **每轮补拍后更新点云。** 将新增照片和本批已确认照片一起送去处理，网页刷新新版本并保留之前的点云。用户打开对应补拍原图，确认新看到的表面，例如玩具背面的贴纸。先做按批提交和刷新，便于确认每份点云来自哪批图。
5. **用这批原图生成完整 3DGS。** 用户确认采集范围后提交异步重建。云端估计相机位姿、优化高斯表示并导出资产。网页加载完成的结果，提供玩具近看、桌面总览和拖动视角三个入口或操作。

以网页上的顺序来看，点云预览是进入最后重建前的检查。以计算输入来看，**点云融合与 3DGS 共用多视角原图，分别生成产物**。经典 3DGS 可用 COLMAP 的稀疏点初始化，并用配准后的原始照片约束外观。 [COLMAP 拍摄与重建](https://colmap.github.io/tutorial.html#structure-from-motion) · [3DGS 原论文](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)

| --- | --- | --- |
| **球形机器人端** | 单 RGB 摄像头、拍照控制、上传、设备在线状态、失败重传。机位移动可以先由操作员控制。 | 球体能换位、停稳、对准同一个玩具。板端和网页都能看到新照片的上传回执。 |
| **目标引导扫描** | 保存目标区域及其照片来源。先按机位标记已拍、待补拍，保留人工修正入口。进阶可分割目标、关联多图中的同一个玩具。 | 点击玩具后能确认扫描目标，知道下一张应该补拍哪个方向。 |
| **单图深度预览** | 云端部署 DA3-BASE，输出相对深度图和着色点云。 | 并排显示原图和深度热图，可旋转看首张照片覆盖的区域。图例红橙偏近、蓝紫偏远，颜色按每张图重新映射。 |
| **多视角点云融合** | 用同批照片联合估计深度与相机参数，对齐后生成多视角点云，输出 GLB。保留首拍及补拍版本。 | 切换单图和多图结果，见到补拍带来的更多表面。页面可打开对应原图。 |
| **3DGS 重建和导航** | 首轮以 COLMAP + Brush 为验证路线。云端环境适合时沿用 Brush，也可验证 Splatfacto。网页用现成高斯查看器加载完整 PLY。 | 可在同一场景里从总览切到玩具近看，绕到覆盖的背面。保存完整资产及可选轻量版。 |
| **网页工作台** | 场景管理、拍摄机位、原图与深度对照、点云版本、3DGS 查看器、进度与失败提示。 | 用户能从选物走到展品回看，每个结果对应到它的真实输入和生成时间。 |
| **虚拟相机仿真** | 用 Three.js 搭小型桌面布景和球形机器人的虚拟相机。允许换机位、拍出当前 RGB 图并提交同一接口。 | 虚拟相机换位置后确实生成新图片，云端处理后刷新对应批次。真机和仿真在页面分别标明来源。 |
| **端云任务与部署** | 板端传照片，GPU 服务运行模型和重建，浏览器交互和渲染。首版可用 FastAPI、SQLite 和持久盘，按批次提交异步任务。 | 能跟踪排队、处理中、成功和失败。断网重传、任务重复提交和失败重试均可复查。 |

### 点云补扫、预测补全和 3DGS 各做什么

- **补扫与融合是首版做法。** 从侧面或背面拍到的新表面进入融合点云。点的位置来自视觉模型的估计，原图用于核对该面确实拍到。首拍与补拍结果可以并排查看，坐标和尺度对齐后再叠加标出新增区域。
- **算法补全属于扩展。** PoinTr 一类方法可以从残缺点云推断可能存在的表面。若后续接入，页面单独标出推断区域和来源。 [PoinTr](https://github.com/yuxumin/PoinTr)
- **3DGS 负责实景外观和新视角渲染。** 以玩具为主体、附近桌面为场景，同一资产先支持近看和总览。如需单独的玩具高斯文件，可从场景中分离目标并另存。需用于三维编辑或仿真碰撞时，另做物件网格和几何检查。 [SuperSplat 选择与裁剪](https://developer.playcanvas.com/user-manual/gaussian-splatting/editing/supersplat/editing-splats/)

## 4. 系统分层和技术路线

~~~mermaid
flowchart LR
    A["球形机器人单目相机"] --> C["采集任务与原图"]
    B["仿真中的虚拟相机"] --> C
    C --> D["DA3-BASE 单图深度与初始点云"]
    C --> E["点选目标与确认机位"]
    E --> F["换位补拍与确认照片批次"]
    F --> G["多视角深度与点云融合"]
    F --> H["COLMAP 相机位姿与 Brush 3DGS"]
    D --> I["网页工作台"]
    G --> I
    H --> I
    I --> J["对照原图、找缺失机位、浏览展品"]
~~~

- **硬件。** 树莓派 4 或 5 可先搭台架接 USB 或 CSI 摄像头。球壳、相机支架、内部驱动、驱动板和移动供电按实际结构定。重点验证相机朝向、不同机位的可达性和停车画面稳定。3D 打印可用于球壳和支架，舵机可用于需要的小云台或表情机构。
- **模型。** DA3-BASE 属于 2025 年公开、发表于 ICLR 2026 的视觉几何模型，可用于单视角与多视角的相对深度和相机参数估计。以此为基础反投影出点云。浏览端可用 Three.js 加载点云，用 SuperSplat 查看 3DGS。 [DA3 论文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/e4cd50120b6d7e8daff1749d6bbaa889-Abstract-Conference.html) · [DA3-BASE 模型卡](https://huggingface.co/depth-anything/DA3-BASE) · [Brush](https://github.com/ArthurBrussee/brush/releases/tag/v0.3.0)
- **任务记录。** 保存场景、来源、目标、照片、拍摄机位、批次、作业和输出。确认后的照片列表保持固定，新增照片生成新版本。失败任务可重试并保留上一份结果。工作台按批次给出原图、深度、点云和 3DGS 的关联。
- **云端与演示机。** 初测可用 24 GB 级 NVIDIA GPU，是否需要更大显存以实测为准。云端用持久盘保存原图和结果，给板端和答辩电脑提供可访问的服务入口。浏览器本地渲染已加载的高斯资产。低带宽时可测试 SOG 压缩，保留同场景的完整版本作画质对照。 [高斯资产格式](https://developer.playcanvas.com/user-manual/gaussian-splatting/formats/)

## 5. 已经验证到哪一步

试验素材是 DA3 官方演示里的 DL3DV 玩具陈列区摄影序列，设备为本机 RTX 4060 Laptop。仿真另用浏览器生成的 RGB 图像。下列数值是本机观察，正式结果以自采玩具、云端环境和赛场网络复测为准。

| 验证项 | 已看到的结果 | 接下来验证什么 |
| --- | --- | --- |
| DA3 单图与多图 | 公开样例单图、8 图、16 图处理并导出的中位数约为 **0.16、0.81、1.65 秒**。工作台可切换不同照片批次并旋转观察。 | 对自己的玩具核对边缘和背面覆盖，再测从上传到页面可交互的完整时间。 |
| 虚拟相机 | 成功从 **4 个机位**导出不同 RGB 图，并跑通过本机 HTTP 上传、提交推理、查询和取回点云。工作台仿真栏可回放实际结果。 | 接入正式任务接口，现场改变虚拟机位并提交新图。 |
| 完整 3DGS | 复跑时 **32 张全部注册**。8,000 步导出 **97,937 个高斯，约 22 MiB**。相机位姿求解约 **23 秒**，训练、评估和导出约 **102 秒**。 | 在真正的球形机器人照片上达到同一场景注册，并清楚显示背面标记和边缘。 |
| 3DGS 实时浏览 | 在本机 Edge、1920 × 1080、RTX 4060 Laptop 下，完整资产三轮测试约 **227–230 渲染帧/秒**，首次显示约 **0.54 秒**。计数取自浏览器渲染，显示器的呈现还受刷新率影响。 | 在答辩电脑测首屏、帧率和连续换视角的稳定性，网络下另测资产下载。 |
| 画质与几何 | 4 个机位参与相机注册，留出于高斯训练并用于渲染评估。8,000 步的平均 PSNR 约 **19.62 dB**、SSIM 约 **0.677**。完整版本轮廓更连续，近看仍可见腿部和货架拉伸。 | 用已知尺寸的样件检查表面几何。为画质对照保留原图、固定视角和相同的训练与评估切分。 |

各阶段的输入、配置和计时口径见[公开样例实测记录](../experiments/public-sample-benchmark.md)。完整和抽样资产的对照来自同一个模型、同一个查看器、同一个机位。完整资产保留了更多轮廓和纹理。首版把**已重建模型的实时浏览**与**每轮补拍后的点云更新**分别验收。高质量 3DGS 作为单独的云端作业，重建耗时和浏览帧率分别记录。

### 从试跑结果做出的取舍

| 看见了什么 | 判断 | 下一次怎么核实 |
| --- | --- | --- |
| 早期样例用长边 900 像素处理，间隔取 16 张时最大子模型是 8 张，全量 32 张时是 27 张。全量 32 张改用长边 1200 后，注册到了一个场景。 | **重建先看照片能否对齐。** 取样和输入尺寸都会影响这组样例，正式机位和分辨率用你们自己的玩具复测。 | 提前选一组正、侧、背面照片，查最大的子模型是否包含关键机位。遇到断开的角度先补拍过渡位置。 |
| 完整高斯的玩具轮廓更连续，腿部和背景仍有拉丝 | **目前更值得改善取景和画质。** 完整版可作为视觉基线，统一对比视角后再换方法。 | 在同一个留出机位比较玩具贴纸、细边和遮挡交界，保留原图和两个模型输出。 |
| 资产在本机加载很快，完整文件约 22 MiB | **本机浏览通过之后，赛场还要过传输这关。** 按 10 Mb/s 估算，单是传输就约 18 秒，实际还会受现场网络和加载开销影响。 | 用答辩电脑测从打开到可拖动的时间。需要压缩时，同机位抽查画质损失。 |
| 相对深度层次正确，高斯近景能看出图案 | **两种结果分别证明前后关系和可见外观。** 几何尺寸需单独测量。 | 选一个有已知宽高、薄边或凹槽的样件，先校准尺度，再记录几何误差。 |

## 6. 画质和表面几何怎么继续做

1. **先控制采集条件。** 用有背面标记、哑光、有细边或凹槽的实物，保持灯光、桌面和物件稳定。从较低机位拍一圈，再补较高机位和缺失角度。检查玩具在画面中是否够大、相邻照片是否重叠、背面照片是否注册到同一个场景。
2. **再做同素材的画质对照。** 用 Brush 作为已跑通的基线，固定训练与留出图，比较完整资产和轻量资产。画质主要看背面标记、轮廓、遮挡边缘和背景拉伸。还可对照不同训练步数或 Improved-GS、SAD-GS。若问题集中在缩放时的锯齿和闪烁，再验证 Mip-Splatting。 [Improved-GS](https://github.com/XiaoBin2001/Improved-GS) · [SAD-GS](https://vcai.mpi-inf.mpg.de/projects/SAD-GS/) · [Mip-Splatting](https://github.com/autonomousvision/mip-splatting)
3. **单独测几何。** 在玩具旁放已知尺寸的参照物，用固定尺度对照实物宽高、薄边和凹槽。若目标变成表面形状更精细或导出网格，可用同一批原图试 2DGS，并检查尺寸误差和表面细节。PSNR、SSIM 用于评估渲染外观，几何用尺寸和表面证据验收。 [2DGS](https://surfsplatting.github.io/)

## 7. 讨论过的扩展想法

当前最值得先做的是**同一目标、机位清单、照片和结果对应**。它们能直接改善现场操作，也容易用实拍结果判断。各项扩展按下面的条件进入开发。

| 想法 | 当前取舍 | 何时值得做 |
| --- | --- | --- |
| **目标分割、跨视角关联与自动识别** | 首版先点选或框选，并允许手动修正。SAM 2 可作为辅助分割候选。 | 玩具经常被背景遮挡，或框内混入较多无关点云时，加入掩码并检查切换到背面后目标是否仍正确。自动命名适合需要管理多个展品时。 [SAM 2](https://github.com/facebookresearch/sam2) |
| **更主动的补拍提示** | 首版用正、侧、背、顶机位清单，并给每一项绑定原图。 | 当相机位姿稳定、前后视角注册可查时，再用位姿和目标遮挡提示实际缺失区域，进一步评估自动规划。 |
| **仿真里移动玩具和改变遮挡** | 虚拟相机换机位是直接有用的验证入口。移动玩具适合独立演示深度变化。 | 仿真用同一上传接口，才能帮助真机联调。滚动、摩擦和控制仿真等结构确定后再试。 |
| **少视角高斯预览、长视频扫描** | DA3-GIANT-1.1 能导出高斯，早期试跑可以浏览，但存在模糊和拉伸。 | 现场确实需要更早看到三维预览时，才独立接快速档。连续定位和地图更新可从 DA3-Streaming 或 MonoGS 评估。 [DA3](https://github.com/ByteDance-Seed/Depth-Anything-3) · [MonoGS](https://github.com/muskie82/MonoGS) |
| **独立玩具资产、单图生成三维道具** | 先把桌面场景里的玩具近看做好。独立高斯可从实景分离，独立网格可另做表面重建。 | 要把展品下载复用或放进仿真时，独立文件才有明确用途。若要从一张照片创作道具，可评估 TRELLIS.2 并注明隐藏表面由生成模型推断。 [TRELLIS.2](https://github.com/microsoft/TRELLIS.2) |
| **扩大实景范围** | 起步范围是一个玩具与一小块桌面。 | 单物件能从新拍照片稳定重建后，再扩大到整张桌面、小展台或一块室内区域，并增加机位覆盖。 |
| **NeRF、单图视角合成** | 保留为相关技术参考。 | 需要和多视角 3DGS 比较新视角画质时可试 NeRF，确实只有一张照片、只看附近视角时可评估 SHARP。 [NeRF](https://www.matthewtancik.com/nerf) · [SHARP](https://github.com/apple-aiml-research/ml-sharp) |
| **数字粒子效果与三维展示** | 优先用颜色或标记提示补拍状态、已采集方向和当前焦点。 | 点云新旧版本对齐后可突出新区域。装饰性交互等核心展示可稳定复演后再评估。 |
| **多模态 LLM 或 Agent** | 当前任务通过明确的按钮和流程即可验收。 | 有多个可查询的展品，或用户确实需要自然语言调度时，可读取真实任务状态来解释拍摄进度。 |
| **避障** | 当前已暂缓。 | 如果将来需要机器人在有障碍物的环境运动，从板端低速遇障停车开始，视机构与测距能力再决定是否做自动绕行。 |

## 8. 开工顺序和现场验收

| 顺序 | 负责人方向 | 可以交给下一步的结果 |
| --- | --- | --- |
| 先拍一个玩具 | 设备与采集 | 用手机拍出清晰的正、侧、背面和相邻机位，确认背面标记有原图可核对。 |
| 跑同批数据 | 模型与部署 | 单图深度、多视角点云和完整 3DGS 都能打开，记录照片注册、耗时和失败原因。 |
| 接入选物和补拍 | 前端与仿真 | 点选一个玩具，看到机位清单与提示，补拍后能回看新旧点云和每张原图。 |
| 接真机与云端 | 三人联调 | 用此前未拍过的玩具，从球形机器人现场拍到网页结果。仿真生成新图并复用同一接口。 |
| 冻结答辩版本 | 三人复核 | 能看首图深度、补拍后新增表面、贴纸在最终高斯实景中的外观。记录首屏、帧率与网络耗时，并核对提交材料。 |

现场用一件背面带贴纸的玩具贯穿全程。先拍正面展示深度，再补拍背面，打开点云和对应原图核对，最后在 3DGS 网页上绕过去看贴纸。如果展示此前计算的完整资产，页面显示原始照片批次和生成时间。

### 逐条核实清单

- [ ] **真机采集**　现场换机位，实物和页面里新照片的角度一致，并能查上传回执。
- [ ] **目标引导**　点选玩具后保存目标。补拍侧面或背面时，界面显示准确的机位状态和对应原图。
- [ ] **深度估计**　用有前后层次的新照片比较原图与热图，确认层次是否合理，并能说明相对深度的含义。
- [ ] **点云融合**　切换补拍前后两个批次。检查新增表面是否能在对应原图中指认。
- [ ] **完整 3DGS**　从同一批现场照片得到可打开的完整资产。切换玩具近看和桌面总览，绕到背面核对贴纸。
- [ ] **仿真**　虚拟相机从两个位置拍出不同图像，使用和真机相同的接口，分别取回实际推理结果。
- [ ] **端云联调**　连续提交和重试能找到正确批次。现场分别记录上传、计算、下载与浏览时长。
- [ ] **画质与几何**　保留同机位原图和完整渲染。若展示表面精度，把经校准的尺寸对照一并附上。
